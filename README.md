# bugprint

**Turn a recorded user session into a failing test that reproduces the bug.**

bugprint is an MCP server for coding agents. You give it a DOM recording of a real user hitting a bug ([rrweb](https://github.com/rrweb-io/rrweb) events). It returns an end-to-end test that replays what the user did and **fails the same way**. The agent fixes the code until the test passes, and the test stays as a regression test.

```
"Can't reproduce" bug report ──▶ bugprint ──▶ failing e2e test ──▶ agent fixes code ──▶ test passes
```

Most session tools stop at *showing* you the recording, and video-based tools have to *guess* what happened from pixels. bugprint works from the recorded DOM itself, so every step resolves to a real element with a stable, human-readable locator.

## What it produces

From [`fixtures/checkout-bug.json`](fixtures/checkout-bug.json), a real 85-event recording of the demo shop:

```text
$ bugprint summarize fixtures/checkout-bug.json
Session ses_64a84b64 · 00:04.6 · 10 steps · 2 page(s)
Pages: / → /checkout.html

[00:00.0] s1   open /
[00:00.8] s2   click button "Add to cart" in listitem "Mechanical Keyboard"
[00:01.1] s3   click button "Add to cart" in listitem "Wireless Mouse"
[00:01.2] s4   click link "Go to checkout"
[00:01.3] s5   → navigated to /checkout.html
[00:02.4] s6   type "user@example.com" into field labelled "Email"
[00:03.2] s7   type "save20" into field labelled "Coupon code"
[00:03.6] s8   click button "Apply"
[00:03.8] s9   check field labelled "I agree to the terms"
[00:04.2] s10  click [data-testid="place-order"]
[00:04.2]   ⚠ uncaught-error: Uncaught TypeError: Cannot read properties of undefined (reading 'rate')  @ HTMLFormElement.<anonymous> (http://localhost:4173/app.js:44:44)
```

```ts
// Generated by bugprint from a recorded user session.
import { test, expect } from '@playwright/test';

const BASE_URL = process.env.BUGPRINT_BASE_URL ?? 'http://localhost:4173';

test('repro: TypeError: Cannot read properties of undefined (reading \'rate\')', async ({ page }) => {
  const errors: string[] = [];
  page.on('pageerror', (err) => errors.push(err.message));
  page.on('console', (msg) => {
    if (msg.type() === 'error') errors.push(msg.text());
  });

  await page.goto(BASE_URL + '/');
  await page.getByRole('listitem').filter({ hasText: 'Mechanical Keyboard' }).getByRole('button', { name: 'Add to cart' }).click();
  await page.getByRole('listitem').filter({ hasText: 'Wireless Mouse' }).getByRole('button', { name: 'Add to cart' }).click();
  await page.getByRole('link', { name: 'Go to checkout' }).click();
  await expect(page).toHaveURL(BASE_URL + '/checkout.html');
  await page.getByLabel('Email').fill('user@example.com'); // redacted
  await page.getByLabel('Coupon code').fill('save20');
  await page.getByRole('button', { name: 'Apply' }).click();
  await page.getByLabel('I agree to the terms').check();
  await page.getByTestId('place-order').click();

  await page.waitForTimeout(300);
  // Recorded in the session:
  //   Uncaught TypeError: Cannot read properties of undefined (reading 'rate')
  expect(errors, 'the page should not throw while replaying the recorded steps').toEqual([]);
});
```

This test fails against the buggy demo app and passes once the bug is fixed. Both runs are part of the demo below.

## Quick start

### 1. Add the MCP server

**Claude Code**

```bash
claude mcp add bugprint -- npx -y bugprint
```

**Cursor / Claude Desktop / any MCP client** (`mcp.json`)

```json
{
  "mcpServers": {
    "bugprint": { "command": "npx", "args": ["-y", "bugprint"] }
  }
}
```

### 2. Ask your agent

> Reproduce the bug in `recordings/checkout.json` against http://localhost:3000, then fix it.

The server also ships a `reproduce_bug` prompt that runs this whole loop: load → summarize → generate → run → fix → re-run.

### 3. Or use the CLI

```bash
npx bugprint summarize recording.json
npx bugprint generate recording.json -o tests/repro/checkout.spec.ts --base-url http://localhost:3000
npx playwright test tests/repro/checkout.spec.ts
```

## Tools

| Tool | What it does |
|---|---|
| `load_session` | Load a recording from a path or inline JSON (event array, `{ events }` or NDJSON). Returns a `sessionId`, the pages visited and any captured errors. |
| `summarize_session` | One line per step, with step ids, timestamps and where errors happened. Far cheaper in tokens than raw events. |
| `extract_flow` | Structured steps with the chosen locator and a confidence score (`high`, `medium`, `low`) for each, plus errors and warnings. |
| `generate_test` | Writes the reproduction test. You can trim it with `fromMs`/`toMs` or `includeSteps`/`excludeSteps`, retarget it with `baseUrl`, and add an expected outcome with `expectVisibleText`. |
| `list_sessions` | Sessions loaded in this server process. |

Agents usually start with `summarize_session` to find the error, then call `generate_test` with only the steps that matter.

## Recording sessions

bugprint reads standard rrweb events. Record the console plugin too, so errors end up in the recording:

```ts
import { record } from 'rrweb';
import { getRecordConsolePlugin } from '@rrweb/rrweb-plugin-console-record';

const events: unknown[] = [];
record({
  emit: (e) => events.push(e),
  plugins: [getRecordConsolePlugin({ level: ['error', 'warn'] })],
});

// Attach `JSON.stringify(events)` to the bug report.
```

[`demo/app/recorder.js`](demo/app/recorder.js) is a small example that stitches several page loads into one recording.

## How it works

```
rrweb events
   │
   ▼
Virtual DOM ─── replays the full snapshot and every mutation, so "node #57" resolves
   │            to what the element looked like at the moment it was clicked
   ▼
Flow extraction ─ collapses 20 keystrokes into one fill, drops focus clicks and
   │              label clicks implied by fill/check, merges click+click+dblclick,
   │              tells page navigations apart from periodic re-snapshots, and
   │              attaches console errors to the step that caused them
   ▼
Locator builder ─ testid → label → role+name → placeholder → text → id → CSS path.
   │              Every candidate is checked for uniqueness against the recorded DOM.
   │              Duplicates are scoped to a container ("button in listitem 'Mouse'")
   │              before falling back to .nth()
   ▼
Code generation ─ BASE_URL indirection, PII redaction, masked passwords moved to env
                  vars, and an assertion that fails on the recorded error
```

Design decisions:

- **Locators are checked against the recording.** bugprint reimplements a subset of the ARIA role and accessible-name rules that the test runner uses, so a locator only counts if it matches exactly one element in the DOM as it was recorded. Every generated locator is resolved back to the clicked node in unit tests.
- **The assertion targets the symptom.** The test fails if the page throws during replay. Before the fix it fails with the user's original error. After the fix it passes, so it works as a regression test without anyone writing an assertion by hand.
- **Output is sized for agents.** `summarize_session` returns a short timeline instead of raw events. Step ids let the agent cut a test down to the steps that matter (`includeSteps: ["s1","s7","s10"]`) without re-reading the recording.
- **Privacy comes first.** Typed e-mails, phone numbers and card numbers are swapped for fakes of the same shape, so client-side validation still behaves the same. This applies to the summaries the agent reads, not only to the generated test. Values that rrweb masked (passwords) become `process.env.BUGPRINT_SECRET_n`.

```bash
npm install
npx playwright install chromium
```

## Limitations and roadmap

Current version (0.1):

- rrweb does not record key presses (Enter, Tab, shortcuts) or URL changes in single-page apps. Navigations are detected from page loads, so SPA route changes show up only through the clicks that caused them.
- Network responses are not part of the recording. The replay runs against your live backend.
- Browser state the session started with (cookies, localStorage, login) is not restored.

Next:

- [ ] `run_and_verify`: run the generated test and confirm it fails with the *same* error before handing it to the agent
- [ ] Network fixtures: capture API responses and replay them with route mocking
- [ ] Freeze time and randomness at their recorded values
- [ ] `minimize_repro`: delta debugging to find the smallest set of steps that still fails
- [ ] Adapters for hosted session-recording services
- [ ] SPA route and keyboard capture through a small recorder plugin
